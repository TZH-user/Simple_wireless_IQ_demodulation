## 2026-05-08 零中频残余相位预补偿方案

- 方案背景：
  - 本振与来波不能做到绝对同频
  - 锁定后仍存在 `mHz` 级残余差频
  - 用户观察到 `I/Q` 两路主幅度会以约 `5~6s` 周期缓慢交换

### 本轮采用方案
- 保留零中频，不立即切到 `low-IF`
- 先落“第一阶段数字补偿”：
  - 以 block 均值矢量为相位观测量
  - 跨 block 累计残余相位
  - 在调制识别链与解调链入口处先做数字反旋转
- 插入位置选择在 `ModDetectTask` / `DemodTask`
  - 保持 `AdcTask` 高频路径不增重
  - 保持 `app_mod_detect.c` / `app_demod_am.c` 现有判据主体不先重写

### 已验证结论
- 对当前“慢速相位旋转、而非快速失锁”的现象，先用共享预处理在低优先级任务层做跨 block 相位预旋转，风险最小
- 该方案主要目标是稳定 `I/Q` 方向与后级参数识别入口，不等价于完整的复数 DC/载波泄漏消除

### 后续保留项
- 若实测后仍存在明显“模长呼吸”或接近归零，再进入第二阶段：
  - 追加复数 DC 矢量/圆心估计
  - 必要时再评估是否切到 `low-IF`

### 经验建议
- 对秒级缓慢残余差频，优先用跨 block 相位跟踪，不要用逐采样 `atan2()` 直接硬累加
- 若后续需要定量观察补偿效果，建议再补一条低频日志，输出残余频偏估计值与 block 均值矢量幅度
- 经验仅供参考，不视为绝对结论

## 2026-05-12 方案修正：相位接管前的“频率稳定”判据

### 问题修正

### 当前判据

  - 窗口第一个有效重心相位作为参考点。
  - 后续每个 block 计算相对该参考点的主值相位差。

- 相位归零阶段继续使用“绝对相位误差”：
  - `phase_error_urad = atan2(Q, I)`。
  - 目标仍为 `0°`，即 IQ 重心落在 `+I` 轴。

### 调试解释
- `phase_rms_urad` 现在表示 3 秒内相位稳定程度，不再表示离 `0°` 多远。
- `phase_error_urad` 仍表示离 `0°` 多远，是相位环接管后的控制输入。

- 原 `APP_CARRIER_SYNC_UPDATE_PERIOD_MS` 同时影响执行间隔和等效积分速度，参数语义不清晰。
- 频率闭环应区分：
  - 控制计算多久执行一次。
  - VRFE 电压每秒最多允许变化多少。

### 当前定义
- `APP_CARRIER_SYNC_FREQ_UPDATE_PERIOD_MS`
  - 频率闭环执行节拍。
  - 默认 `20 ms`。
- `APP_CARRIER_SYNC_FREQ_SLEW_UV_PER_SEC`
  - 频率闭环积分斜率。
  - 默认 `5000 uV/s`，即 `5 mV/s`。
- 实际单次步进由公式得到：
  - `step_uv = APP_CARRIER_SYNC_FREQ_SLEW_UV_PER_SEC * elapsed_ms / 1000`

### 调参建议
- 想让闭环更快：优先增大 `APP_CARRIER_SYNC_FREQ_SLEW_UV_PER_SEC`。
- 想让 DAC 输出更平滑：减小 `APP_CARRIER_SYNC_FREQ_UPDATE_PERIOD_MS`，但不要靠周期改变闭环速度。
- 想降低 CPU/串扰风险：增大 `APP_CARRIER_SYNC_FREQ_UPDATE_PERIOD_MS`，同时按需要保持或调整斜率。

## 2026-05-12 方案更新：频率闭环改为 PI

### 当前控制结构
- 当前频率闭环已从“符号限速积分”改为 PI 控制。
- 输入仍为 `app_iq_preproc_result_t.residual_freq_millihz`。
- 输出仍为 DAC1 对 OCXO VRFE 的控制电压 `control_uv`。

### PI 对应关系
- P 项：
  - `p_term_uv = APP_CARRIER_SYNC_CONTROL_POLARITY * residual_freq_millihz * APP_CARRIER_SYNC_FREQ_KP_UV_PER_HZ / 1000`
  - 作用：频偏越大，即时修正越大。
- I 项：
  - `i_term_uv += APP_CARRIER_SYNC_CONTROL_POLARITY * residual_freq_millihz * APP_CARRIER_SYNC_FREQ_KI_UV_PER_HZ_S * elapsed_ms / 1000000`
  - 作用：残余频偏持续不为 0 时慢慢消除静差。
- 目标电压：
  - `target_uv = APP_CARRIER_SYNC_CENTER_UV + p_term_uv + i_term_uv`
- 实际输出：
  - `control_uv` 不直接跳到 `target_uv`，而是受 `APP_CARRIER_SYNC_FREQ_SLEW_UV_PER_SEC` 限速逼近目标。

### 当前不是 PID
- 当前没有 D 项。
- 原因：`residual_freq_millihz` 本身有测量噪声，D 项容易放大抖动；OCXO VRFE 是慢对象，先用 PI 更稳妥。

### 调参顺序建议
- 先确认 `APP_CARRIER_SYNC_CONTROL_POLARITY` 方向正确。
- 再调 `APP_CARRIER_SYNC_FREQ_KP_UV_PER_HZ`，观察响应速度和是否过冲。
- 再调 `APP_CARRIER_SYNC_FREQ_KI_UV_PER_HZ_S`，消除长期静差。
- 最后用 `APP_CARRIER_SYNC_FREQ_SLEW_UV_PER_SEC` 限制 DAC 电压变化速度，保护 OCXO 不被快速拉动。

## 2026-05-13 相位闭环方案变更记录：从固定步进改为基准电压 DPLL

### 背景

- 目标：频率闭环稳定后，以 I 正幅度为 x 正半轴的 IQ 坐标系进行绝对相位闭环。
- 当前调试目标暂选 90 度，即 +Q 轴；原因是 0 度附近容易出现正负跨越和符号误判，90 度更便于先验证 VRFE 相位可控性。
- 前提门控保持不变：扫频锁定、`carrier_present=1`、残余频偏稳定后才允许相位接管。

### 方案变化

1. 测量方式
   - 从重心相位改为逐点相位圆均值。
   - 实现上不对每个点直接调用 `atan2f()`，而是把每个有效点归一化成单位向量后累加，最后用一次 `atan2f()` 得到平均相位。
   - 这样可以正确处理相位跨越，同时计算量可由 `APP_CARRIER_PHASE_SAMPLE_STEP` 控制。

2. 控制方式第一版：固定步进
   - 直接根据相位误差正负号，每次改变 DAC 若干 uV。
   - 实测问题：接近目标后不减速，OCXO 频率偏置继续积分成相位漂移，导致穿过目标后继续转。

3. 控制方式第二版：继承频率闭环电压作为基准
   - 相位接管瞬间记录 `phase_base_uv = control_uv`。
   - 相位环只在 `phase_base_uv` 附近施加 `phase_trim_uv_q` 小数 uV 修正，不再无边界叠加当前 DAC。
   - 实测收益：`uv` 不再大幅扫动，ADC 实时性未恶化。
   - 实测不足：初始修正太弱，不能抵消已存在的相位速度。

4. 控制方式第三版：加入相位速度阻尼
   - 新增 `phase_delta_mdeg` 表示相邻有效 block 的相位误差变化。
   - `phase_control_mdeg = phase_error_mdeg + APP_CARRIER_PHASE_DPLL_RATE_LEAD * phase_delta_mdeg`。
   - 用 `phase_control_mdeg` 更新内部小数 uV 修正量，再限幅到每次最大 `APP_CARRIER_PHASE_DPLL_MAX_STEP_UV`。
   - 实测状态：方向有改善迹象，但尚未稳定锁住目标。

### 当前参数与对应现象

- `APP_CARRIER_PHASE_TARGET_MDEG=90000`：当前锁 90 度。
- `APP_CARRIER_PHASE_SAMPLE_STEP=16`：每个 4096 点 block 抽约 256 点，日志中 `u=256`。
- `APP_CARRIER_PHASE_MIN_RESULTANT_PM=150`：当前 CW 下日志 `rel=1000`，说明相位测量质量充分。
- `APP_CARRIER_PHASE_DPLL_MAX_STEP_UV=2`：保护 VRFE 不被快速拉飞。
- `APP_CARRIER_PHASE_DPLL_INTEGRAL_SCALE_MDEG_PER_UV=90000`：比 900000 版本强约 10 倍；900000 过慢，90000 仍未完全闭合。
- `APP_CARRIER_PHASE_DPLL_RATE_LEAD=128`：用于提前制动；当前仍需继续根据日志调试。

### 后续建议

- 不再盲目增加固定步进；相位环需要围绕“相位速度是否减小”调参。
- 下一步优先增加更细的状态观测，例如每 100ms 输出一次相位 DPLL 摘要，或通过 STLINK 直接观察 `g_carrier_sync_status_dbg.phase_delta_mdeg`、`phase_control_mdeg`、`phase_delta_uv`。
- 若 `phase_delta_mdeg` 长期同号且目标被反复穿过，应继续增大阻尼或翻转/修正控制极性。
- 若 `uv` 长期贴近 `phase_base_uv ± APP_CARRIER_PHASE_DPLL_TRIM_LIMIT_UV`，说明相位环修正范围不够或频率闭环交接点偏离，需要先重新评估频率闭环稳态。

## 2026-05-13 03:45 相位 DPLL 方案补充：禁止双任务叠加，改为单写入者合成控制

### 方案判断

- 不采用“频率闭环任务 + 相位闭环任务分别计算 DAC，最后相加”的结构。
- 原因：两个实时路径同时修改同一 VRFE 控制量，容易形成竞态和互相抵消；即使用锁保护，也会让 ADC block 时序和调参含义变复杂。
- 当前坚持一个 DAC 写入者：`app_carrier_sync_update_iq()` 内部判断模式，最终只通过 `app_carrier_sync_apply_uv()` 写一次 DAC。

### 本轮调整

- 相位模式继续继承频率闭环最后的 `control_uv`，不回中心。
- residual 频偏先低通为 `phase_freq_lpf_millihz`，再作为相位模式下的频率制动项。
- 相位环极性改为 `APP_CARRIER_PHASE_CONTROL_POLARITY=-1`；该结论来自串口实测，`+1` 会把相位误差继续推离 90°。
- 串口新增 `carx` 行，用于判断相位模式是否真的在减速、是否触发目标附近制动、是否存在频偏重新变大的问题。

### 本轮结论

- 已验证：相位计算可靠，接管状态可观测，ADC 未见堆积，极性翻转后可接近 90°。
- 未解决：接近目标后 residual 仍可能重新增大，导致相位继续绕圈。
- 下一步不建议继续盲目调大/调小步进；应先增加“相位模式频偏保护退出”或改成更明确的二状态 PLL：

```text
频率闭环压 residual -> residual 稳定窗口满足
进入相位闭环 -> 只允许小范围相位微调
若相位模式 residual 重新变大 -> 退出相位闭环，回到频率闭环
```

## 2026-05-13 0 度相位锁定方案：目标 residual 轨迹环

### 方案判断

- 0 度比 90 度更符合最终解调坐标：`atan2(Q, I)=0` 时，I 路位于正半轴，Q 路接近 0。
- 直接按相位误差积分调 DAC 已验证容易绕圈；本轮改为“相位误差生成目标 residual，DAC 只负责追踪目标 residual”。
- 不采用频率环和相位环两个任务并行相加，继续保持单一 DAC 写入者，避免竞态和调参含义混乱。

### 控制流程

```text
扫频锁定
  -> 频率闭环把 residual 压到稳定门限
  -> phase_wait 计数满足
  -> phase_lock 继承当前 DAC 电压
  -> 计算绝对相位 current_phase = atan2(Q, I)
  -> phase_error = wrap(0 - current_phase)
  -> 生成小目标 residual
  -> 用 residual 低通值追踪目标 residual
  -> 接近 0 度后目标 residual 置 0
```

### 远区防抖

- 当绝对相位进入 ±170 度附近时，启用远区方向保持。
- 远区内不按瞬时 `+179/-179` 符号翻转方向，而是沿上一有效方向继续推一小段。
- 相位离开 ±150 度后恢复最短路径控制。

### 当前参数

- `APP_CARRIER_PHASE_TARGET_MDEG=0`
- `APP_CARRIER_PHASE_SETTLE_MS=6000U`
- `APP_CARRIER_PHASE_TARGET_RESIDUAL_MAX_MHZ=50`
- `APP_CARRIER_PHASE_LOCK_BAND_MDEG=2000`
- `APP_CARRIER_PHASE_RESIDUAL_DEADBAND_MHZ=5`
- `APP_CARRIER_PHASE_FAR_ENTER_MDEG=170000`
- `APP_CARRIER_PHASE_FAR_EXIT_MDEG=150000`
- `APP_CARRIER_PHASE_RESIDUAL_POLARITY=1`

### 验收观察

- `car,m=phase_lock` 后，`carp,ph` 应逐步靠近 `0.000`。
- `carx,tr` 应随 `carp,er` 变小而减小，接近目标后变为 0。
- `carx,dcd/chg` 用来判断 DAC code 是否真实变化，不能只看 `uv`。
- `carq,u/rel` 用来判断逐点相位计算是否可靠；CW 下应长期接近 `u=256,rel=1000`。
